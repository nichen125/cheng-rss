# AI RSS

自托管的 RSS 阅读与 AI 分析工具。阅读体验对齐 Huntly，并在此之上提供自动化的
分类分级、每日简报、跨篇聚合。支持二进制 / 源码 / Docker 三种部署，一个数据目录
即可备份迁移。

> **当前状态：M0 完成**（骨架 + 三路部署 + 认证 + 队列 + 检索 + 首版 UI）。
> 按 [PLAN.md](PLAN.md) 的分步计划推进，M1 已完成 1.1~1.13。订阅抓取、AI 分析、简报
> 在 M1~M3 落地。

## 快速开始

### 方式 A：源码运行（开发推荐）

需要先有 Node 24。**所有依赖与工具链都装在项目目录内**，不污染系统。

```bash
git clone <repo> && cd ai-rss

# Linux / macOS
./scripts/bootstrap.sh      # 下载项目内 Node 24（约 34MB，只需一次）
./scripts/build.sh          # 构建前端 + 服务端
./.toolchain/node/bin/node --experimental-strip-types src/index.ts serve --data ./data

# Windows PowerShell
.\scripts\bootstrap.ps1
.\scripts\build.ps1
.\.toolchain\node\node.exe --experimental-strip-types src\index.ts serve --data .\data
```

打开 http://127.0.0.1:3000 ，首次访问会引导创建管理员账号。

### 方式 B：单文件二进制

```bash
./scripts/build.sh --sea               # 产出 dist/ai-rss-<platform>-<arch>[.exe]
./dist/ai-rss-linux-x64 serve --data ./data --port 3000
```

二进制内嵌了全部前端资源，**不需要旁边的 dist 目录**，复制单个文件即可运行。

### 方式 C：Docker

```bash
docker compose up -d
# 或
docker build -t ai-rss . && docker run -d -p 3000:3000 -v ./data:/app/data ai-rss
```

## 配置中心

订阅管理、分组、账户都收在一个弹窗里（左边选分类，右边改内容）。
点侧栏底部齿轮，或点侧栏/底部导航的「订阅」——都打开它，后者直接停在
「订阅」分类。

| 分类 | 现在能做什么 |
|---|---|
| 订阅 | 源列表、添加、编辑、批量管理、OPML 导入导出、全部刷新 |
| 分组 | 新建 / 重命名 / 删除，显示每组源数 |
| 账户 | 邮箱、显示名、角色、退出登录 |
| AI 分析 | 占位（M2）：模型 API、分类分级、重跑队列、提示词模板 |
| 每日简报 | 占位（M3）：生成时间与推送、聚合范围、跨源冲突、历史回看 |
| 备份与迁移 | 占位（M6）：备份保留份数、一键导出、恢复到干净实例、校验和 |

为什么是弹窗而不是加一栏：配置是低频动作，常驻一栏会永久吃掉 1/4 屏宽；
弹窗把主界面遮住，明确告诉你"现在在配置，不是在读"。

**切分类不会丢东西**：六个分类都挂着，只把非当前的藏起来。所以你在
「添加订阅」里填了一半地址、跑去「分组」看一眼再回来，输入还在。

**订阅页的分组筛选有两种形态**：分组 ≤ 2 个时是一排 chip（一次点击到
目标）；≥ 3 个时换成下拉栏 —— chip 行会随分组数换行，把源列表往下压，
而这一行的作用只是"选一个分组"。

## 收件箱阅读控制

列表标题行右侧有「全部 / 未读」和刷新按钮。

- **全部 / 未读**：同一个列表的筛选，不是两个页面。点「未读」只留未读，
  点「全部」把已读的也放回来（已读的仍是灰的，一眼能区分）。它和侧栏的
  「未读」是同一份状态，点哪边另一边都会跟着变。
- **刷新**：重新拉当前视图，**保留**你现在的分组 / 源 / 搜索词。刷新时
  列表不会清空（不闪白），按钮转圈并禁用，防止连点。

为什么放标题行而不是单开一行：按 §15.2 的密度预算，一屏要看 8~10 条，
多一行控件就等于每屏少一条。

刷新和切视图的区别：切视图是**换条件**，刷新是**同一条件重新取数**。
所以读完一篇在别处被标成已读的文章，点一下刷新就能看到它的新状态。

## 分组与编辑

几十个源之后，必须能归拢。分组是**一层扁平结构**（没有嵌套），理由是
一层就够用，而嵌套会让拖拽和删除的边界情况翻倍。

### 建分组

侧栏齿轮「配置」→「分组」→ 输入名字 →「新建」。（也可以从侧栏「订阅」
进配置后点左边的「分组」。）重名会被拒绝（大小写不敏感），避免
「把这个源放进『科技』」变成有歧义的操作。

### 把订阅放进分组

两条路都行：

- **添加时直接选**：「+ 添加订阅」面板里有「分组」下拉，一次到位。
  默认跟随当前筛选 —— 你正看「科技IT」时加源，它就会落进「科技IT」。
- **事后改**：订阅行 → 铅笔图标 → 选分组 → 保存。同一个弹窗里还能改：

| 字段 | 说明 |
|---|---|
| 标题 | 留空则显示域名。RSS 自带的标题经常又长又带站点后缀，改短更好扫 |
| 分组 | 未分组 / 已有分组 |
| 抓取间隔 | 5 分钟 ~ 7 天。频繁更新用 30，周更博客用 1440 |

### 按分组看文章

侧栏「分组」下点组名 → 列表只显示该组的条目。标题旁有一个小小的 × 可以
退回全部。固定的「收件箱/未读/已收藏/历史」等价于"看全部"，点它们会
自动清掉分组筛选。

### 看分组里的某个订阅

选中分组后，标题下方会出现一行 chip：最左边是「全部」，后面是组里每个源，
每个 chip 上都标着**该源的未读数**（0 也会显示 —— "这个源没新内容"本身
就是你想知道的信息）。

点一个源 → 列表只剩它的条目，标题变成「组名 · 源名」；再点同一个源
就回到整组。组里只有一个源时不显示这行（一行 chip 只为过滤到一个源
没有意义）。

有两点在实现时特意处理过：

- **两个条件是真的叠加**。请求同时带 `folderId` 和 `feedId`，交集为空就
  返回 0 条，不会退化成"满足任一"。所以"组A + 组C的源"是空列表而不是错乱。
- **筛选态会自愈**。你正筛着某个源，然后去配置里把它移出组 —— 回来时
  会自动退回"整组"，**但分组保留**。不自愈的话顶部还挂着那个源的 chip，
  列表永远是空的；自愈时顺手把分组也清掉，你会以为自己被弹出了分组。

### 删分组

在配置 →「分组」里删。组里的订阅**不会**被删，会退回「未分组」。
这是刻意的：删分组是最容易误触的操作，让它连带删掉 20 个订阅是灾难。

### OPML 带上分组

导出时会保留分组层级（分组是一个包住订阅的 outline），换到别的阅读器
后分组还在。导入同理——按名字复用已有分组，重名不报错。

## 一键批量管理

导入 OPML 之后第一件事不是读文章，而是把 20~30 个源收拾一遍。逐行点
五下 ×30 行没人做得完，所以有批量模式。

配置 →「订阅」→「管理」→ 每行左侧出勾选框，顶部出批量栏：

| 操作 | 说明 |
|---|---|
| 全选 / 清空 | 作用于**当前筛选后**的源。先点「科技IT」再全选，只选这 3 个 |
| 组头勾选框 | 只选这一个分组，不动其它组 |
| 移到分组… | 下拉里选目标组；选「未分组」即移出 |
| 恢复 / 暂停 | 恢复 `broken` 的源会同时清零错误计数并让下次抓取立刻到期 |
| 刷新 | 入抓取队列；暂停的源自动跳过（刷新它们等于假装刷了） |
| 删除 | 唯一需要确认的操作，确认框会写明"未读 N 条会一起删" |

**为什么是四个批量接口而不是前端循环**：32 个源移进分组时前端循环调用，
第 17 个失败（并发写锁）就变成"一半在组里"——用户还得手动找出来哪个没进去。
批量接口在一个事务里做完，要么全成要么全不成，而且只走一个往返。

混入已删除的 id 不会整体失败（另一个标签页刚删掉一个源不该阻断这次操作），
但会在结果里报 `missing`，不会静默吞掉。

## 阅读页

### 两个出口：原文 与 源站

读完一篇后想继续看的地方有两种，对应两个不同的入口：

| 入口 | 去哪 | 在哪 |
|---|---|---|
| 打开原文 | 这篇文章本身 | 阅读栏 `↗` / 标题 / 文末按钮 / 快捷键 `v` |
| 去源站 | 这个订阅的站点首页 | 阅读栏 `<RSS 图标>` / 站点名 / 文末「访问源站」 |

两者都是新标签打开，不离开阅读器。网页捕获的条目（没有源）不渲染源站入口，
不是渲染一个死链。

### 正文里的链接不再把阅读器跳走

改之前实测：正文 3176 个链接里有 2196 个（69%）**没有 `target`**，点一下就在
主框架里导航走了 —— 当前筛选、已加载的列表、滚动位置全部丢失，得按浏览器
后退才回得来。点一次就丢上下文，体感等同于"链接不能点"。

现在在清洗层统一加 `target="_blank"`，两类例外：

- **页内锚点**（`#xxx`）：同一文档内定位，新开标签等于把用户丢进一个只有片段
  的新页。清洗是幂等的（详情接口每次请求都会重洗一遍），所以第二次看到它
  already 是绝对 URL 时也要能认出来 —— 这是实现里最容易翻车的一处。
- **`mailto:` / `tel:`**：交给系统处理，浏览器本来就不导航。

### 列表行可以用中键打开

行元素是 `div[role=button]`（不是 `<button>`），标题是真 `<a href>`：

- 左键点行任意处 → 在右侧阅读区打开（原行为不变）
- **中键 / Ctrl+点击标题 → 在新标签打开原文**（浏览器原生行为）
- `Tab` 能聚焦到行，`Enter` 打开

为什么不能直接往 `<button>` 里塞一个 `<a>`：HTML 内容模型禁止交互元素嵌套。
所以这不是"加个链接"，是必须换行元素，再把按钮语义（`role` + `tabindex` +
Enter/Space）手工补回来。

### 已读可回退

阅读栏有「标为未读」按钮，快捷键 `m`。误点开一篇之后不用再去改数据库。

**阅读历史不清零**：`first_read_at` / `last_read_at` / `read_count` 保持原样。
"读过了"是事实，"不想让它算未读"是视图层的意图，两者不能互相污染 ——
否则 unread 一次就把「历史」页里的记录抹了。

### 阅读偏好

阅读栏 → 设置图标，三项都只影响阅读区、只存本机：

| 项 | 可选 |
|---|---|
| 字号 | 小 15 / 中 16.5（默认）/ 大 18 / 特大 20 |
| 正文宽度 | 60 / 72（默认）/ 84 字符 |
| 底色 | 跟随系统 / 亮 / 米色 / 暗 |

不存服务端的理由：这是"这台设备上看着舒服"，不是账号数据。存服务端会立刻
出问题 —— 通勤时在手机上把字号调大，桌面端的 72ch 布局也跟着乱。

### 快捷键

| 键 | 行为 |
|---|---|
| `/` | 聚焦搜索框 |
| `j` `↓` / `k` `↑` | 下一篇 / 上一篇 |
| `Esc` | 返回列表 |
| `s` | 收藏 |
| `v` | 新标签打开原文 |
| `m` | 切换已读 / 未读 |
| `t` | 列表回到顶部 |
| `o` `Enter` | 当没有打开的文章时，打开第一条 |

字母键在输入框里全部失效（否则打字会触发跳页）；带 Ctrl/Cmd/Alt 的组合键也
不参与（否则 `Ctrl+V` 会被当成"打开原文"）。

## 添加订阅

启动后打开 UI → 侧栏「订阅」→「+ 添加订阅」，贴任何地址都行：

（这一步打开的是配置弹窗，停在「订阅」分类。面板里的「分组」下拉可以直接把新源放进某个组。）

| 你贴的 | 会发生什么 |
|---|---|
| 完整 feed URL（`https://x.com/feed.xml`） | 直接订阅 |
| 网站首页（`https://sspai.com`） | 从页面 `<link rel="alternate">` 找订阅地址 |
| 裸域名（`sspai.com`） | 补 `https://` 再按首页处理 |
| 一段带 URL 的文字 | 抠出第一个 URL |
| 找不到 `<link>` 的站点 | 探测 `/feed` `/rss` `/atom.xml` 等 14 个常见路径 |

发现到**多个** feed 时会让用户选，不替他挑。订阅前会先真抓一次 ——
拉不到内容的源不会进列表，所以"订阅成功但空的"不会发生。

也可以导入别的阅读器导出的 OPML（文件夹层级会保留），或导出自己的订阅。

### 抓取行为

| 行为 | 值 | 说明 |
|---|---|---|
| 默认间隔 | 30 分钟 | 添加后可改，最小 5 分钟 |
| 条件请求 | ETag / Last-Modified | 304 时不重复入库，也不消耗解析 |
| 失败退避 | 间隔 × (1 + 失败数×2)，最多 7 倍 | 成功一次即复位 |
| 置 `broken` | 连续 3 次失败，或 404/410 | 不再自动重试，UI 标「失效」 |
| 取消订阅 | 未读条目删除；**已读/已收藏保留** | 历史记录不该因为退订而消失 |

正文在入库前过白名单清洗（`feeds/sanitize.ts`），读出来时再洗一次 ——
feed 是外部输入，`<script>`、`onerror`、`javascript:` 都必须拦掉。

## 兼容 Huntly 浏览器插件

在官方 Huntly 插件的设置里把服务器地址改成 `http://<你的地址>:3000`，即可用：
连接、保存网页、查看已保存角标、收藏。

不需要改插件代码。已实现的核心端点：

```
GET  /api/auth/loginUserInfo     未登录返回 200 + null（不是 401）
POST /api/auth/login             返回裸用户对象 + Set-Cookie
GET  /api/auth/checkUserExist
```

其余端点（归档、稍后读、集合、黑名单）在 M7 补完。

> 注意：这是逆向出的兼容层，无官方契约。Huntly 改字段就会断，需要靠 HAR 契约
> 测试发现（M7）。

#### 关于 `m0-09-ui` 的浏览器依赖

它用本机 Edge/Chrome 的**无头模式 + 裸 CDP** 验布局，不下载 playwright。
找不到 Chromium 系浏览器时整节 SKIP（退出 0）并打印说明 —— 环境缺失不算失败，
但 SKIP 会在汇总里看得见，不会静默通过。

为什么需要它：其余脚本全是行为断言（状态码、字节数、耗时），一个布局错乱、
正文只有 66 字符宽、或者点开条目就跳页的界面能让 9/9 全绿。

#### 关于 `docker-path` 的产物验证

它需要一份 **linux 版 node** 作为 SEA 的注入底本（约 25MB），用来验证
Dockerfile 里 `build-sea` 那一步真能产出能跑的 ELF。首次运行：

```bash
node scripts/fetch-linux-node.mjs      # 一次，之后走 .tmp/linuxnode 缓存
node scripts/verify-all.mjs            # 这时 docker-path 是 12/12
```

**没有这份 node 时，`docker-path` 会报 FAIL 而不是假装通过** ——
"没验证"和"验证通过"是两件事。离线环境可显式接受跳过：

```bash
node scripts/verify-all.mjs --allow-skip-docker-artifact
```

此时会明确提示"这不等于构建路径已验证"。

### 跨平台构建

SEA 的注入底本必须是目标平台的 node 可执行体。所以：

```bash
# 在 Windows 上造 Windows 产物（默认）
node scripts/build-sea.mjs

# 在 Windows 上造 Linux 产物：需要一份 linux 的 node
AI_RSS_SEA_BASE=./vendor/node-linux-x64 \
  node scripts/build-sea.mjs --target linux-x64

# 不提供底本时会明确拒绝，而不是产出一个跑不起来的文件
node scripts/build-sea.mjs --target linux-x64
# ✗ 不能从 win32-x64 造 linux-x64 的二进制。
```

Docker 构建天然满足这一点（容器里跑的就是 linux node），所以 `Dockerfile` 里
直接写 `--target linux-x64`。

## 技术选型要点

| 选择 | 原因 |
|---|---|
| Node 24 LTS（非 Bun） | `node:sqlite` 内置、SEA 单二进制、LTS 承诺 |
| `node:sqlite` + Drizzle `1.0.0-rc.5` | 无原生插件；**0.45.x 没有 `node-sqlite` 驱动** |
| Hono（非 Next.js） | 纯 Request→Response，可打成单文件 |
| FTS5 + 程序侧 bigram | `trigram` 查不到 2 字中文（实测返回 0 条） |
| 正文 gzip BLOB | 实测压缩 2.6×，占全库体积 84% 的部分必须压 |
| SEA + `assets` + fflate | Node 24 的 SEA **没有** `vfsArchive`（Node 26 才有） |

详细依据见 [PLAN.md](PLAN.md) 第三章。

## 已知限制

- **SEA 不支持 Alpine（musl）**：Docker 用 `debian:bookworm-slim`
- **不发布 macOS 二进制**：SEA 官方只测 arm64
- **Docker 镜像未在真机上构建过**：开发机没装 docker。Dockerfile 的每条指令已
  本地逐条验证（`scripts/verify/docker-path.mjs`），并且**真的产出了能内嵌资源的
  linux-x64 ELF**，但 `docker build` 本身没跑过。首次在有 docker 的机器上构建时
  请留意：若失败，最可能的原因是 `package-lock.json` 与容器内 npm 版本差异。
- **订阅已可用**：RSS 2.0 / Atom / RDF、OPML 导入导出、自动发现地址、定时抓取、条件请求
- **AI 分析仍待 M2**：「AI 摘要」卡片目前只在演示数据里出现，真实抓取的条目没有分析结果
- **正文提取是简化版**：feed 自带全文就直接清洗入库；只有摘要时**不会**去抓原网页跑 Readability，
  这项在 M1 后续步骤补齐（`m1-08-extract`）
- **去重只有 URL 与标题指纹两层**，向量余弦判重在 M1 后续步骤（`m1-09-dedupe`）
- 侧栏的「简报」标灰注明"待接入"，点了不会有反应（不是 bug，是明确标注的未实现）
