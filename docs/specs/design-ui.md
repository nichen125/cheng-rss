# 澄 · 界面设计方案

> 文件：`docs/specs/design-ui.md`
>
> 本文是**规格**，不是变更记录。它描述界面应当长成什么样、为什么，以及如何检验。
> 实现细节（类名、文件组织）可以变，这里的约束不能悄悄变；要变就先改这份文档。

---

## 一、定位

**澄**是一个私人知识库管理工具。RSS 是它的**入口**，不是它的身份。

信息从订阅流进来，AI 压一遍，留下来的才是你的。界面要服务这条链路上的三种动作：

| 动作 | 用户在想什么       | 界面该给什么             |
| ---- | ------------------ | ------------------------ |
| 扫   | "今天有什么值得看" | 密度、时间感、AI 的判断  |
| 读   | "这篇在讲什么"     | 安静、可长时间停留的正文 |
| 留   | "以后我还会用到它" | 收藏、高亮、可回看的位置 |

三种动作对应三个区域，一屏并置，不做跳转。这不是审美选择：RSS 阅读最高频的动作是"读完一篇挑下一篇"，跳页式导航会把它变成两次点击，并且每次都丢失滚动位置。

**产品名不使用缩写，也不出现 "RSS"。** 界面上的字标是「澄」，其下是一行小字「私人知识库」。技术标识（二进制名、镜像名、UA）另属工程范畴，不在本方案的约束之内。

## 二、设计原则

### 2.1 颜色只表达「AI 的判断」，不表达「可点击」

界面里唯一允许出现饱和色的地方，是 AI 给出的分级：

- 必读
- 值得

其余一切——导航、链接、按钮、选中态——都只用墨色与灰阶。可点击由**形状与位置**表达（下划线、边框、指针、悬停背景），不由颜色表达。

理由：一个处处是强调色的界面，等于没有强调色。当唯一有颜色的东西是"AI 认为这条重要"时，用户扫一遍列表就能看见 AI 的判断，而不需要读文字。

推论：**链接不使用强调色**。正文外链用下划线，按钮用边框或反白。

### 2.2 时间是结构，不是元信息

列表左侧保留一条窄栏，竖排显示当天的日号；跨月时出现一次月界标签。

- 日号用衬线体，星期用无衬线小字。
- 每行**不再重复"3 小时前"**作为主要时间信号，只在同一日内保留相对时间。
- 换日产生一条明显的水平分层。

理由：「3 小时前」回答的是"这条多新"，而「这是哪一天」回答的是"我漏了几天"。后者才是知识库用户真正关心的，而且它只需要看一次，不需要每行都看。

### 2.3 两种字体，两种任务

| 区域                      | 字族   | 任务     |
| ------------------------- | ------ | -------- |
| 列表、导航、控件、元信息  | 无衬线 | 快速扫描 |
| 正文、标题、AI 摘要、日号 | 衬线   | 沉浸阅读 |

无衬线在密集小字下更利落，衬线在长文里更耐读。一个阅读器全文用无衬线，是在为扫描优化、为阅读付代价。

### 2.4 AI 摘要属于文章，不是浮在文章上

AI 摘要不采用卡片形态（边框、阴影、圆角、折叠箭头），而是**正文之前的一段引言**：

- 一道 2px 强调色标线在左
- 一行小字标签 `AI 摘要`（强调色、字距 0.12em）
- 衬线正文，颜色比正文暗一阶
- 要点为无项目符号的小行，用 3px 圆点起头

理由：卡片会把它读成"嵌进来的外部组件"。引言体会让它读成"这篇文章的一部分"——事实上它确实是。

### 2.5 克制

一次只让一处显眼。整屏最亮的东西应当是**正文标题**，其次是当前选中项。其余全部退到灰阶里。

动效只服务于状态变化的连续性，不超过 150ms，并遵守 `prefers-reduced-motion`。

## 三、色彩

### 3.1 亮色是主色

理由不是审美偏好，而是使用场景：这个工具的正文超过七成是在白天、办公室、
外接屏上读的。暗底白字在那种环境下只是看起来"酷"，长时间读并不舒服。

三层底色，靠明度差分隔，不靠粗线条：

| 令牌            | 值        | 用途                         |
| --------------- | --------- | ---------------------------- |
| `--bg-sunken`   | `#f7f8fa` | 侧栏、阅读区桌面（退后一层） |
| `--bg`          | `#ffffff` | 列表、内容面                 |
| `--bg-elev2`    | `#f3f5f8` | 输入框、分段控件底色         |
| `--bg-hover`    | `#f1f3f7` | 悬停                         |
| `--bg-active`   | `#e8ecf2` | 按压                         |
| `--fg`          | `#14171c` | 正文                         |
| `--fg-dim`      | `#58616e` | 次级文字                     |
| `--fg-faint`    | `#8c95a3` | 元信息                       |
| `--border`      | `#e4e8ee` | 描边                         |
| `--border-soft` | `#eef1f5` | 行分隔                       |
| `--paper-bg`    | `#ffffff` | 阅读纸面                     |
| `--paper-line`  | `#e9edf3` | 纸面内的线                   |
| `--desk-bg`     | `#f7f8fa` | 纸面之外的桌面               |

侧栏比内容区**暗**一阶：三栏并排时靠明度分带比靠三条竖线干净，
而且滚动的长列表不会在边界处出现"线在动"的错觉。

### 3.2 暗色跟随系统

不是主色，但必须完整：夜里看长文的人会切换系统主题，界面跟不上就会刺眼。

| 令牌          | 值        |
| ------------- | --------- |
| `--bg`        | `#15171c` |
| `--bg-sunken` | `#0f1115` |
| `--bg-elev`   | `#1a1d23` |
| `--fg`        | `#e9ecf1` |
| `--fg-dim`    | `#a4adba` |
| `--border`    | `#2a2f38` |
| `--paper-bg`  | `#1a1d23` |
| `--desk-bg`   | `#0f1115` |

### 3.3 强调色只出现在三处

`--accent` 亮色 `#0f766e`、暗色 `#4fd1c5`。它只用于：

1. 主按钮（`--accent` 实心 + 白字）
2. 当前导航项（淡乏力底色 `--accent-soft` + 强调色字）
3. 正文外链与 AI 块的左侧标线

其余一律是灰阶。一个界面里强调色出现得越少，它指的地方才越明确。

### 3.4 含义色

| 令牌      | 亮色      | 暗色      | 含义 |
| --------- | --------- | --------- | ---- |
| `--must`  | `#c2410c` | `#f97362` | 必读 |
| `--worth` | `#a16207` | `#d9a441` | 值得 |

只出现在分级标记上，形态是「4px 圆点 + 两字标签」，不是实心胶囊。

## 四、字体

### 4.1 字族

```
--serif: "Noto Serif SC", "Source Han Serif SC", "Songti SC", STSong, simsun, Georgia, serif;
--sans:  "Noto Sans SC", -apple-system, BlinkMacSystemFont, "Segoe UI",
         "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--mono:  ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace;
```

无外部字体请求：全部依赖系统已有字族。等宽只用于数字、时间、`kbd`、标签小字，靠它把数字对齐。

### 4.2 尺度

| 位置        | 字族   | 字号   | 行高 | 字重            |
| ----------- | ------ | ------ | ---- | --------------- |
| 字标「澄」  | 衬线   | 25px   | 1.1  | 600，字距 .14em |
| 字标副行    | 无衬线 | 10.5px | —    | 400，字距 .22em |
| 栏标题      | 无衬线 | 16px   | —    | 600             |
| 导航项      | 无衬线 | 13.5px | —    | 400 / 选中 500  |
| 列表标题    | 无衬线 | 14px   | 1.45 | 500             |
| 列表摘要    | 无衬线 | 12px   | 1.45 | 400             |
| 列表元信息  | 无衬线 | 11px   | 1.4  | 400             |
| 时间        | 等宽   | 10.5px | —    | 400             |
| 文章标题    | 衬线   | 30px   | 1.36 | 600             |
| AI 摘要正文 | 衬线   | 15px   | 1.8  | 400             |
| 正文        | 衬线   | 16.5px | 1.86 | 400             |

正文高度比例（1.86）比原规格略松，因为衬线体的 x-height 更小，同一行高下视觉更紧。

### 4.3 数字对齐

所有会变化的数字（角标、条数、时间、日期）使用 `font-variant-numeric: tabular-nums`。等宽数字让刷新后的列表不左右跳动。

## 五、布局

### 5.1 三栏

```
┌────────┬────────────────┬──────────────────────────┐
│ 侧栏   │ 列表           │ 阅读区                   │
│ 196px  │ 368px          │ 纸面 712px 居中 + 目录   │
└────────┴────────────────┴──────────────────────────┘
```

宽度沿用已实测收敛的数值：侧栏 196px、列表 368px。二者都是"最坏情况"下的取值，再多就是空白。

阅读区不放固定宽度，纸面 `max-width: 80ch`（`content-box`），目录在右侧 150px，两者作为一组居中。

### 5.2 侧栏

```
▢ 澄  KNOWLEDGE            ← 印章方块 + 字名

 ◯ 收件箱            527   ← 选中：淡强调色底 + 强调色字
 ◯ 未读              527
 ☆ 已收藏            142
 ◯ 历史
 ✦ 简报

订阅源
 ⌄ 订阅              22

分组
 · 散源甲             12   ← 未分组源在最前，无展开箭头
 · 散源乙              3
 ⌄ 科技 IT            59   ← 分组行，按 sort 排
    源 A               21
    源 B               38
 ⌄ 长知识              9
 ⌄ 编程              301
 ⌄ 独立博客          121

──────────────────────
 ◯ Owner
   admin@localhost
```

- 侧栏底色比内容区**暗一阶**，靠明度分带而不是竖线分隔三栏。
- 激活项是**实心淡强调色底 + 强调色字**。这个位置一天要看几十次，
  值得给一块有重量的底色；一道竖线太轻，扫视时找不到"我在哪"。
- 角标用等宽小字、无底色：一颗有背景的圆点会把视线吸到"还有多少没读"上，
  而那个数字是压力源，不是导航。
- 滚动条自绘 6px：系统默认滚动条在亮色下是一条 15px 的灰带，切在侧栏边缘
  比边界线还粗，等于把分层又破坏一次。
- 字标由一个方块 + 字名组成，方块里是三道逐级变短的横线——浑浊静置后
  逐层沉底，这正是"澄"这个字在做的事。
- **未分组源排在最前**，不带展开箭头。它们没有层级，位置本身就是说明；
  加一行「未分组」标签要吃掉 20px，而区块标题已经在上面了。

#### 5.2.1 排列模式

长按分组行或源行 500ms 进入。侧栏的区块标题换成「调整顺序 · 完成」，
每行左侧箭头位换成拖柄，右侧角标换成 ↑↓。

```
调整顺序                    完成
 ⠿ 散源甲              ↑ ↓   ← 拖柄 + 微调
 ⠿ 散源乙              ↑ ↓
 ⠿ 科技 IT             ↑ ↓   ← 拖着源悬停在这一行 = 放进该组
 ⠿ 长知识              ↑ ↓
```

进入之后有四个阶段，每个阶段都必须有信号——否则用户不知道"现在归我手管"：

| 阶段       | 表现                                                        |
| ---------- | ----------------------------------------------------------- |
| 长按触发   | 该行浮起（`--bg-elev` + 阴影 + 放大 1.02），其余行降到 0.72 |
| 拖动中     | 浮起卡片跟指针；原位置留淡色占位，不是整行消失              |
| 悬停行间   | 目标行边缘一条 2px 强调色落点线                             |
| 悬停分组行 | 整行染 `--accent-soft` + 一圈强调色描边，表示"放进去"       |

落点线与整行高亮**不能合并成一种**：前者是"换个位置"，后者是"换个归属"，
结果差别很大。两者长得一样时用户分不出松手会发生什么。

跨组移动后底部弹一条 toast，2.6 秒后消失，带「撤销」。同组内纯调序不弹——
原地挪一格弹一条比不弹更吵。

排列模式下**行高、字号、缩进一律不变**。进入这个动作本身不许把侧栏撑高，
否则光是进模式就挤掉一屏条目。

**手机上没有侧栏**（≤640px），排列模式在手机上不存在。手动排序的入口在
配置 › 分组：每行常显 ↑↓，展开分组后组内源也有 ↑↓ 和「移到…」下拉。

### 5.3 列表

```
十一月 ───────────────────────────
 │
02    S 奇客Solidot · 25 分钟    ● 值得
周六  欧洲夏季热浪导致逾 5 万城市居民死亡
      今年夏天热浪席卷欧洲大部分地区…

      R ruanyf/weekly · 26 分钟  ● 必读
      [文章自荐] Agent 已完成却被判失败…
      投稿一篇个人开源项目中的工程案例…
│
01    ...
周日
```

- 左栏 52px，右侧一道竖线贯穿当日全部行。
- 日号字形 17px 衬线，星期 11px 无衬线。
- 行高不设固定值，由内容决定；密度目标是 1440×900 下一屏 9 条。
- 选中行左侧 2px 强调色标线，背景 `--accent-soft`（悬停用 `--bg-hover`）。
- 已读行标题降为 `--fg-dim`、字重 400，整行不降透明度（降透明度会让摘要糊成一片）。
- **元信息行永远是单行**：站点 · 时间 · 分级。三者里只有站名可以收缩并加省略号；
  时间和分级是定长信息，不换行、不压缩。允许它们换行会让「13 小时前」从空格处
  折成两行，行高 22px → 62px，一屏条数从 9 掉到 6。

### 5.4 阅读区

```
 ←        [✦ 摘要][✦ 总结]      ↗  ☰  ◯  ☆   ← 工具条
   ┌────────────────────────────────────────┐  目录
   │ [文章自荐] Agent 已完成却被判失败：    │  ────
   │ 一个可复现的状态读取竞态               │  竞态是怎么发生的
   │                                        │  确定性复现
   │ 胡涂涂 · 2026-11-02 15:13              │  同行快照校验
   │ ─────────────────────────────────────  │  三个相关边界
   │ ▏AI 摘要  ● 必读                       │
   │ ▏ReelPilot 把视频素材检索、剪辑计划…   │
   │ ▏ · 取消 Future 并不能强制停止…        │
   │                                        │
   │ 投稿一篇个人开源项目中的工程案例…      │
   └────────────────────────────────────────┘
```

**AI 动作收成一组放在工具条右侧。** 「摘要」「总结」两个按钮拼成一段，
它们是"对这篇文章做点什么"，与返回、收藏、设置同属工具条，而非文章内容。
之前总结按钮埋在纸面里、摘要折叠头埋在正文上方，两个 AI 动作分居两处，
用户找不到"这类功能在哪"。

- 摘要的显示由工具条上的「摘要」按钮控制，纸面里**不再有折叠头**。
- 总结的触发也在工具条上；纸面里只渲染结果，不再重复一个"总结"标题按钮。
- 一个动作只有一个入口。按钮与内容分居两处，会让人以为它们是两件事。

**AI 摘要与总结共用一套语言**：一行小标签（强调色、字距 0.12em）+ 一段引言，
左侧一道 2px 强调色标线，不画卡片边框。摘要是"这篇文章的一部分"，
画框会把它读成一个嵌进来的外部组件。

**正文外链才加下划线。** 列表里的标题不加——一屏十条，每条挂一条下划线
就变成十条横线，比没有层级更难扫；可点击由整行悬停底色表达。

### 5.5 批注与高亮

划词后工具条贴着选区上方浮出：三枚色点 + 一个「批注」。

**批注在工具条内联展开**，不用浏览器原生 `prompt`：

- 原生对话框样式不受控，在白底界面里突然弹出一块系统灰框
- 原生 prompt 的「取消」只返回 null，用户看不到自己写了什么被丢掉

内联输入框配「取消 / 保存」两个按钮，`Esc` 等同取消，`Enter` 等同保存。
取消会**丢弃草稿**并把输入框还原到已保存的值 —— 不这么做的话，
改了一半点取消、再点「加批注」会看到上次的草稿，用户会以为取消没生效。

高亮列表在正文末尾，每条是「色点 + 原文两行 + 批注」；编辑态里同样有
「删除 / 取消 / 保存」三个动作，`Esc` 退出编辑。

### 5.6 阅读偏好面板

顶部一条工具带，四行：字号 / 宽度 / 底色 / 恢复默认。分段控件用 `--radius-sm`，选中项为 `--accent-dim` 底 + 墨字。

## 六、组件尺度

| 控件                | 高度 | 圆角            |
| ------------------- | ---- | --------------- |
| 文字按钮（主 / 次） | 32px | 8px             |
| 图标按钮            | 32px | 8px             |
| 迷你图标按钮        | 22px | 4px             |
| 输入框              | 32px | 8px             |
| 胶囊（chip / 徽标） | —    | 999px           |
| 卡片 / 弹窗         | —    | 12–16px         |
| 纸面                | —    | 16px            |
| 列表行              | —    | 0（相邻行共边） |

规则是**同类控件同圆角、圆角随尺寸单调**，而不是"统一成一个数"。小于 24px 的控件不许用 6px 圆角。

## 七、动效

| 场景         | 时长  | 曲线                  |
| ------------ | ----- | --------------------- |
| 悬停 / 激活  | 110ms | linear                |
| 列表进入     | 120ms | ease-out，opacity 0→1 |
| 折叠展开     | 150ms | ease                  |
| 刷新图标旋转 | 700ms | linear，循环          |

不做入场编排、不做视差、不做滚动触发动画。`prefers-reduced-motion: reduce` 下全部降到 0.01ms。

## 八、响应式

### 8.1 三档断点

| 宽度       | 布局                                     |
| ---------- | ---------------------------------------- |
| > 1280px   | 三栏 + 侧边目录                          |
| 900–1280px | 三栏，隐藏侧边目录，纸面自适应           |
| < 900px    | 侧栏 + 列表，阅读区为全屏浮层            |
| < 640px    | 单列列表 + 底部 tab 条，阅读区为全屏浮层 |

响应式规则集中在 `mobile.css`，桌面规则集中在 `styles.css`。两处各写一套断点会互相覆盖出难以复现的中间态。

### 8.2 移动端不是桌面缩小版

| 桌面         | 手机                | 原因                          |
| ------------ | ------------------- | ----------------------------- |
| 左侧栏       | 底部 tab 条（5 项） | 390px 下侧栏吃掉一半宽度      |
| 三栏并排     | 列表 / 阅读互斥     | 三栏在 390px 下每栏不到 130px |
| hover 出操作 | 操作常驻            | 触摸没有 hover                |
| 日期栏 52px  | 收窄到 44px         | 把宽度还给标题                |

硬约束：触摸目标 ≥ 44px、输入框字号 ≥ 16px、底部留白 ≥ 56px + 安全区、横向溢出为 0、横屏（`max-height: 480px` 且 `max-width: 900px`）隐藏侧栏与 tab 条。
