# 澄 · 界面设计方案

> 文件：`docs/specs/design-ui.md`
>
> 本文是**规格**，不是变更记录。它描述界面应当长成什么样、为什么，以及如何检验。
> 实现细节（类名、文件组织）可以变，这里的约束不能悄悄变；要变就先改这份文档。

---

## 一、定位

**澄**是一个私人知识库管理工具。RSS 是它的**入口**，不是它的身份。

信息从订阅流进来，AI 压一遍，留下来的才是你的。界面要服务这条链路上的三种动作：

| 动作 | 用户在想什么       | 界面该给什么             |
| ---- | ------------------ | ------------------------ |
| 扫   | "今天有什么值得看" | 密度、时间感、AI 的判断  |
| 读   | "这篇在讲什么"     | 安静、可长时间停留的正文 |
| 留   | "以后我还会用到它" | 收藏、高亮、可回看的位置 |

三种动作对应三个区域，一屏并置，不做跳转。这不是审美选择：RSS 阅读最高频的动作是"读完一篇挑下一篇"，跳页式导航会把它变成两次点击，并且每次都丢失滚动位置。

**产品名不使用缩写，也不出现 "RSS"。** 界面上的字标是「澄」，其下是一行小字「私人知识库」。技术标识（二进制名、镜像名、UA）另属工程范畴，不在本方案的约束之内。

## 二、设计原则

### 2.1 颜色只表达「AI 的判断」，不表达「可点击」

界面里唯一允许出现饱和色的地方，是 AI 给出的分级：

- 必读
- 值得

其余一切——导航、链接、按钮、选中态——都只用墨色与灰阶。可点击由**形状与位置**表达（下划线、边框、指针、悬停背景），不由颜色表达。

理由：一个处处是强调色的界面，等于没有强调色。当唯一有颜色的东西是"AI 认为这条重要"时，用户扫一遍列表就能看见 AI 的判断，而不需要读文字。

推论：**链接不使用强调色**。正文外链用下划线，按钮用边框或反白。

### 2.2 时间是结构，不是元信息

列表左侧保留一条窄栏，竖排显示当天的日号；跨月时出现一次月界标签。

- 日号用衬线体，星期用无衬线小字。
- 每行**不再重复"3 小时前"**作为主要时间信号，只在同一日内保留相对时间。
- 换日产生一条明显的水平分层。

理由：「3 小时前」回答的是"这条多新"，而「这是哪一天」回答的是"我漏了几天"。后者才是知识库用户真正关心的，而且它只需要看一次，不需要每行都看。

### 2.3 两种字体，两种任务

| 区域                      | 字族   | 任务     |
| ------------------------- | ------ | -------- |
| 列表、导航、控件、元信息  | 无衬线 | 快速扫描 |
| 正文、标题、AI 摘要、日号 | 衬线   | 沉浸阅读 |

无衬线在密集小字下更利落，衬线在长文里更耐读。一个阅读器全文用无衬线，是在为扫描优化、为阅读付代价。

### 2.4 AI 摘要属于文章，不是浮在文章上

AI 摘要不采用卡片形态（边框、阴影、圆角、折叠箭头），而是**正文之前的一段引言**：

- 一道 2px 强调色标线在左
- 一行小字标签 `AI 摘要`（强调色、字距 0.12em）
- 衬线正文，颜色比正文暗一阶
- 要点为无项目符号的小行，用 3px 圆点起头

理由：卡片会把它读成"嵌进来的外部组件"。引言体会让它读成"这篇文章的一部分"——事实上它确实是。

### 2.5 克制

一次只让一处显眼。整屏最亮的东西应当是**正文标题**，其次是当前选中项。其余全部退到灰阶里。

动效只服务于状态变化的连续性，不超过 150ms，并遵守 `prefers-reduced-motion`。

## 三、色彩

### 3.1 亮色是主色

理由不是审美偏好，而是使用场景：这个工具的正文超过七成是在白天、办公室、
外接屏上读的。暗底白字在那种环境下只是看起来"酷"，长时间读并不舒服。

两级底色（企业简洁风的硬约束：画布与卡片必须不同色，白卡片才浮得起来）：

| 令牌             | 值                   | 用途                                  |
| ---------------- | -------------------- | ------------------------------------- |
| `--bg-sunken`    | `#f8fafc` Slate Mist | 页面画布、侧栏、阅读区桌面            |
| `--bg`           | `#ffffff` White Card | 列表、卡片、面板                      |
| `--bg-elev2`     | `#f1f5f9`            | 输入框、分段控件底                    |
| `--bg-hover`     | `#f1f5f9`            | 悬停                                  |
| `--bg-active`    | `#e2e8f0`            | 按压                                  |
| `--bg-selected`  | `#eff6ff`            | 列表选中行（浅蓝一档）                |
| `--fg`           | `#0f172a`            | 正文（17.85:1）                       |
| `--fg-dim`       | `#334155`            | 标题、次级正文（10.35:1）             |
| `--fg-faint`     | `#64748b` Slate      | 说明、元信息、图标描边（4.76:1）      |
| `--border`       | `#e5e7eb`            | 卡片描边                              |
| `--border-soft`  | `#f1f5f9`            | 行分隔                                |
| `--border-input` | `#d1d5db`            | 输入框描边（比卡片深一档）            |
| `--focus-ring`   | `#3b82f6`            | 焦点环（Action Blue，不做大面积填充） |
| `--ring-offset`  | `#f8fafc`            | 焦点环与元素之间的 2px 留白           |
| `--paper-bg`     | `#ffffff`            | 阅读纸面                              |
| `--desk-bg`      | `#f8fafc`            | 纸面之外的桌面                        |

侧栏与阅读区桌面都是 Slate Mist，卡片是白 —— 层次由「底色差 + 1px 边框 + 两级阴影」
三件事共同建立，其中阴影只有 `0 1px 2px`（rest）与 `0 4px 12px`（hover）两级。

### 3.2 暗色跟随系统

不是主色，但必须完整：夜里看长文的人会切换系统主题，界面跟不上就会刺眼。

沿用同一套 slate 家族，只是把明度反转：画布最暗、卡片抬一档。

| 令牌             | 值        |
| ---------------- | --------- |
| `--bg`           | `#1e293b` |
| `--bg-sunken`    | `#0f172a` |
| `--bg-elev`      | `#1e293b` |
| `--bg-elev2`     | `#243245` |
| `--fg`           | `#f1f5f9` |
| `--fg-dim`       | `#cbd5e1` |
| `--fg-faint`     | `#94a3b8` |
| `--border`       | `#334155` |
| `--border-input` | `#475569` |
| `--accent`       | `#60a5fa` |
| `--paper-bg`     | `#1e293b` |
| `--desk-bg`      | `#0f172a` |

**暗色必须提亮主色**：`#1e40af` 在 `#1e293b` 上只有 2.1:1。`#60a5fa` 是 5.75:1。

### 3.3 强调色只出现在三处

`--accent` 亮色 `#1e40af` Corporate Blue、暗色 `#60a5fa`。
**全站只有一种蓝**：主按钮、链接、当前导航项、关键图标同源。
`#3b82f6` Action Blue 只做焦点环与选中高亮，**不做大面积填充** ——
同一页面出现两种主色蓝是这套体系最容易犯的错。它只用于：

1. 主按钮（`--accent` 实心 + 白字）
2. 当前导航项（淡乏力底色 `--accent-soft` + 强调色字）
3. 正文外链与 AI 块的左侧标线

其余一律是灰阶。一个界面里强调色出现得越少，它指的地方才越明确。

### 3.4 含义色

| 令牌       | 亮色      | 暗色      | 含义                     |
| ---------- | --------- | --------- | ------------------------ |
| `--must`   | `#1e40af` | `#93c5fd` | 必读（= 主色）           |
| `--worth`  | `#64748b` | `#94a3b8` | 值得（= Slate）          |
| `--ok`     | `#10b981` | `#34d399` | 成功 / 已同步            |
| `--warn`   | `#d97706` | `#fbbf24` | 提示                     |
| `--err`    | `#dc2626` | `#f87171` | 失败 / 破坏性动作        |
| `--violet` | `#c559f0` | —         | 实验性功能标签，极少使用 |

分级徽标是企业风的 **Status Badge** 形态：胶囊、12px / 500、`padding: 4px 10px`。
「必读」= 浅蓝填充 + 企业蓝字；「值得」= 1px 描边不填充（hint 形态）；噪音不出徽标。
**永远带一个小圆点**，不只靠颜色传达状态 —— 色弱用户也要读得出来。

## 四、字体

### 4.1 字族

```
--font-sans: "Inter", ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
             "Segoe UI", Roboto, "PingFang SC", "Microsoft YaHei", sans-serif;
--serif:     "Source Han Serif SC", "Noto Serif SC", "Songti SC", STSong,
             Georgia, "Times New Roman", serif;
--mono:      ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace;
```

**界面文字只用 Inter 一档**（缺失时回落系统 UI 字体，中文落到苹方 / 雅黑）。
层级靠 400 / 500 / 600 / 700 四档字重与字号建立，不靠堆颜色。

正文仍用衬线：这是本项目的立身之处 —— 扫描用无衬线、阅读用衬线。
企业简洁风只管界面，不管正文（§2.3）。

无外部字体请求：全部依赖系统已有字族。等宽只用于数字、时间、`kbd`、标签小字。

### 4.2 尺度

字号阶梯只有六个值：**12 / 13 / 14 / 16 / 17 / 18 / 20 / 24 / 30**。
9~11.5px 的微缩档一律抬到 12 —— 它们是「老旧感」最直接的来源，
在 100% 缩放的普通屏上只能勉强辨认，读起来像被压扁的密集表格。

| 位置        | 字族   | 字号   | 行高 | 字重             |
| ----------- | ------ | ------ | ---- | ---------------- |
| 字标「澄」  | 衬线   | 25px   | 1.1  | 600，字距 .14em  |
| 字标副行    | 无衬线 | 12px   | 1.2  | 500，字距 .08em  |
| 栏标题      | 无衬线 | 16px   | 1.4  | 600              |
| 导航项      | 无衬线 | 14px   | 1.6  | 500              |
| 分区标题    | 无衬线 | 12px   | 1.4  | 600，字距 .06em  |
| 列表标题    | 无衬线 | 14px   | 1.4  | 500              |
| 列表摘要    | 无衬线 | 13px   | 1.5  | 400              |
| 列表元信息  | 无衬线 | 12px   | 1.35 | 400              |
| 时间        | 等宽   | 12px   | —    | 400              |
| 文章标题    | 衬线   | 30px   | 1.42 | 600，字距 .01em  |
| 正文 h2     | 衬线   | 21px   | 1.45 | 600              |
| 正文 h3     | 衬线   | 18.5px | 1.45 | 600              |
| AI 摘要正文 | 衬线   | 15px   | 1.8  | 400              |
| 正文        | 衬线   | 17px   | 1.8  | 400，段距 1.25em |

**唯一一处刻意偏离企业规范**：正文 17px / 1.8，而不是 16px / 1.65。
那套值是给表单与后台表格的；中文衬线长文需要更松的行距，
否则整页读起来像合同。界面文字全部遵循 16 / 1.65 那一档。

### 4.3 数字对齐

所有会变化的数字（角标、条数、时间、日期）使用 `font-variant-numeric: tabular-nums`。等宽数字让刷新后的列表不左右跳动。

## 五、布局

### 5.1 三栏

```
┌────────┬────────────────┬──────────────────────────┐
│ 侧栏   │ 列表           │ 阅读区                   │
│ 196px  │ 368px          │ 纸面 712px 居中 + 目录   │
└────────┴────────────────┴──────────────────────────┘
```

宽度沿用已实测收敛的数值：侧栏 196px、列表 368px。二者都是"最坏情况"下的取值，再多就是空白。

阅读区不放固定宽度，纸面 `max-width: 80ch`（`content-box`），目录在右侧 150px，两者作为一组居中。

### 5.2 侧栏

```
▢ 澄  KNOWLEDGE            ← 印章方块 + 字名

 ◯ 收件箱            527   ← 选中：淡强调色底 + 强调色字
 ◯ 未读              527
 ☆ 已收藏            142
 ◯ 历史
 ✦ 简报

订阅源
 ⌄ 订阅              22

分组
 · 散源甲             12   ← 未分组源在最前，无展开箭头
 · 散源乙              3
 ⌄ 科技 IT            59   ← 分组行，按 sort 排
    源 A               21
    源 B               38
 ⌄ 长知识              9
 ⌄ 编程              301
 ⌄ 独立博客          121

──────────────────────
 ◯ Owner
   admin@localhost
```

- 侧栏底色比内容区**暗一阶**，靠明度分带而不是竖线分隔三栏。
- 激活项是**实心淡强调色底 + 强调色字**。这个位置一天要看几十次，
  值得给一块有重量的底色；一道竖线太轻，扫视时找不到"我在哪"。
- 角标用等宽小字、无底色：一颗有背景的圆点会把视线吸到"还有多少没读"上，
  而那个数字是压力源，不是导航。
- 滚动条自绘 6px：系统默认滚动条在亮色下是一条 15px 的灰带，切在侧栏边缘
  比边界线还粗，等于把分层又破坏一次。
- 字标由一个方块 + 字名组成，方块里是三道逐级变短的横线——浑浊静置后
  逐层沉底，这正是"澄"这个字在做的事。
- **未分组源排在最前**，不带展开箭头。它们没有层级，位置本身就是说明；
  加一行「未分组」标签要吃掉 20px，而区块标题已经在上面了。

#### 5.2.1 排列模式

长按分组行或源行 500ms 进入。侧栏的区块标题换成「调整顺序 · 完成」，
每行左侧箭头位换成拖柄，右侧角标换成 ↑↓。

```
调整顺序                    完成
 ⠿ 散源甲              ↑ ↓   ← 拖柄 + 微调
 ⠿ 散源乙              ↑ ↓
 ⠿ 科技 IT             ↑ ↓   ← 拖着源悬停在这一行 = 放进该组
 ⠿ 长知识              ↑ ↓
```

进入之后有四个阶段，每个阶段都必须有信号——否则用户不知道"现在归我手管"：

| 阶段       | 表现                                                        |
| ---------- | ----------------------------------------------------------- |
| 长按触发   | 该行浮起（`--bg-elev` + 阴影 + 放大 1.02），其余行降到 0.72 |
| 拖动中     | 浮起卡片跟指针；原位置留淡色占位，不是整行消失              |
| 悬停行间   | 目标行边缘一条 2px 强调色落点线                             |
| 悬停分组行 | 整行染 `--accent-soft` + 一圈强调色描边，表示"放进去"       |

落点线与整行高亮**不能合并成一种**：前者是"换个位置"，后者是"换个归属"，
结果差别很大。两者长得一样时用户分不出松手会发生什么。

跨组移动后底部弹一条 toast，2.6 秒后消失，带「撤销」。同组内纯调序不弹——
原地挪一格弹一条比不弹更吵。

排列模式下**行高、字号、缩进一律不变**。进入这个动作本身不许把侧栏撑高，
否则光是进模式就挤掉一屏条目。

**手机上没有侧栏**（≤640px），排列模式在手机上不存在。手动排序的入口在
配置 › 分组：每行常显 ↑↓，展开分组后组内源也有 ↑↓ 和「移到…」下拉。

### 5.3 列表

**一行显示多少信息，由「列表」密度偏好决定（v6.6）。** 三档：

```
          ┌──────────────────────────────────────┐
11月      │ 欧洲夏季热浪导致逾 5 万城市居民死亡  │  compact
02        │                                      │  43~64px
周六      │                                      │  一屏 13~14 条
          └──────────────────────────────────────┘
          ┌──────────────────────────────────────┐
          │ 奇客Solidot · 25 分钟    ● 值得       │
          │ 欧洲夏季热浪导致逾 5 万城市居民死亡  │  standard（默认）
          │                                      │  103~130px
          │ 今年夏天热浪席卷欧洲大部分地区…      │  一屏 8 条
          └──────────────────────────────────────┘
          ┌──────────────────────────────────────┐
          │ 奇客Solidot · 25 分钟    ● 值得       │
          │ 欧洲夏季热浪导致逾 5 万城市居民死亡：│
          │ 一个可复现的状态读取竞态             │  rich
          │                                      │  164~220px
          │ 今年夏天热浪席卷欧洲大部分地区，多地  │  一屏 5 条
          │ 刷新了历史同期最高气温记录，气象部门  │
          │ 已连续发布高温红色预警…               │
          └──────────────────────────────────────┘
```

**月份只在跨月那一行出现**（v6.7）。每行都带是二十次噪声；一次都不带，
滚动时就永远不知道现在是几月。实现是 `.day-mark[data-month-start]::before { content: attr(data-month) }`
—— 属性只在换月那一行渲染，其余行连属性都没有。

**标题与摘要之间永远有一段空白**（v6.7）：standard 8px、rich 12px。
贴住的话，两行标题 + 一行摘要会读成一个三行的段落 —— 这条与密度档无关，
三档都必须有。

三档不是"三个开关"，而是**三套排版组合**（行内边距 / 标题行数 /
摘要行数 / 分隔线深浅一起变）。一侧是"扫得最快"，另一侧是"不用点开就能挑"，
取决于此刻是在浏览还是在挑选 —— 所以都留，让人自己切。

**一行的字号档数是有预算的。** standard 档里摘要沿用 12px（与元信息同档），
靠颜色 `--fg-faint` 而非字号退后 —— 三种字号挤在一行里，每扫一行要切三次，
那正是列表"乱"的来源。

- 左栏 46px，右侧一道竖线贯穿当日全部行（`left: 45px`）。
- 日号字形 16px 衬线、500，星期 12px 无衬线、`--fg-faint`。
- **一行只显示标题**（v6.5），最多两行，超出省略。
  行高：单行 43px、两行 62px、带日号的当天首行 64px，1440×960 下一屏 13 条。
- **不显示 favicon**（v6.3）。13px 的彩色图标是这一行唯一的彩色像素，
  十几个不同的图标排在左侧，眼睛会先被它们吸走再看标题；站名用文字就够。
- **compact 档下摘要不显示、元信息退到 `.entry-meta` 的裁剪态**
  （1px + `clip-path`）：读屏要念、历史视图的 `meta` 插槽要用、
  验收脚本要取 —— 用 `display: none` 会把它们从无障碍树里一起删掉。
  组件**始终渲染三部分**，显示多少只由 `<html data-list-style>` 决定：
  密度是显示偏好，不是数据差异，按偏好条件渲染会让切换变成整列表重渲染。
- 选中行左侧 2px 墨线，背景 `--bg-selected`（悬停用 `--bg-hover`）。
- 行内操作（收藏 / 新标签打开）绝对定位在行的垂直中线右侧，
  常驻 `padding-right: 44px` 给它让位 —— 不常驻的话它一出现标题就重排、整栏上下跳。
  触摸屏（≤640）上常驻显示并放大到 30px。
- **日号栏绝对定位**（v6.6）。它 33px 高、元信息行只有 16px，只要在网格里
  占一格，当天首行就会被撑高 15px。`left: 0; top: var(--entry-pad-y)`，
  与文字起点共用同一个变量，三档密度下都对齐且不参与行高。
**列表滚动到底自动加载（v6.8）。** 底部不再是按钮，而是 1px 哨兵 + 一行状态提示：

| 状态   | 显示                                       |
| ------ | ------------------------------------------ |
| 加载中 | `⟳ 正在加载…`（固定 44px 高）              |
| 已到底 | `没有更多了`（`--fg-faint`、透明度 .7）    |
| 失败   | `加载失败` + `重试` 按钮（唯一可点的一档） |

用 `IntersectionObserver` 而不是 `scroll` 事件，三个理由：

1. `scroll` 每条事件都要量 `scrollTop + clientHeight + scrollHeight`，
   那是每帧一次强制同步布局；observer 由合成线程算。
2. observer 天然处理"内容不够高、根本不出滚动条"的情形 —— 哨兵一开始就在
   可见区内，立刻触发。用 `scroll` 时那种情况**永远不会**触发。
3. `rootMargin: 0px 0px 320px 0px` 是提前量：等哨兵真进可见区才请求，
   用户会先看到一帧空白。320px ≈ 三四行，请求在路上时正好读完当前几行。

哨兵必须在**正常流里**（不是 `absolute`、不是 `display: none` 的容器里）：
那两种情况下它不产生交叉，observer 一次都不会触发。

- 列表栏宽三档 368 / 456 / 544，写进 `--list-w-user`，再由
  `--list-w: clamp(300px, var(--list-w-user), calc(100vw - var(--sidebar-w) - 656px))`
  夹住。三段各管一件事：300 是下限（再窄列表就不成其为列表）；用户值是期望；
  656 是正文预留（正文列 574 + 左右内边距 82），意思是**列表先让、正文后让**。
  **断点不覆盖 `--list-w`** —— v6.6 那样写（≤1220 时硬给 344）等于把用户的
  选择整个丢掉，在笔记本上切三档毫无反应，那正是「不论什么档位宽度不变」的成因。
  已知行为：视口 ≤1240 时三档收敛到同一个值，因为再宽就挤掉正文了。
- 已读行标题降为 `--fg-dim`、字重 400，整行不降透明度（降透明度会让摘要糊成一片）。
- **元信息行永远是单行**：站点 · 时间 · 分级。三者里只有站名可以收缩并加省略号；
  时间和分级是定长信息，不换行、不压缩。允许它们换行会让「13 小时前」从空格处
  折成两行，行高 22px → 62px，一屏条数从 9 掉到 6。

### 5.4 阅读区

```
 ←        [✦ 摘要][✦ 总结]      ↗  ☰  ◯  ☆   ← 工具条
   ┌────────────────────────────────────────┐  目录
   │ [文章自荐] Agent 已完成却被判失败：    │  ────
   │ 一个可复现的状态读取竞态               │  竞态是怎么发生的
   │                                        │  确定性复现
   │ 胡涂涂 · 2026-11-02 15:13              │  同行快照校验
   │ ─────────────────────────────────────  │  三个相关边界
   │ ▏AI 摘要  ● 必读                       │
   │ ▏ReelPilot 把视频素材检索、剪辑计划…   │
   │ ▏ · 取消 Future 并不能强制停止…        │
   │                                        │
   │ 投稿一篇个人开源项目中的工程案例…      │
   └────────────────────────────────────────┘
```

**AI 动作收成一组放在工具条右侧。** 「摘要」「总结」两个按钮拼成一段，
它们是"对这篇文章做点什么"，与返回、收藏、设置同属工具条，而非文章内容。
之前总结按钮埋在纸面里、摘要折叠头埋在正文上方，两个 AI 动作分居两处，
用户找不到"这类功能在哪"。

- 摘要的显示由工具条上的「摘要」按钮控制，纸面里**不再有折叠头**。
- 总结的触发也在工具条上；纸面里只渲染结果，不再重复一个"总结"标题按钮。
- 一个动作只有一个入口。按钮与内容分居两处，会让人以为它们是两件事。

**AI 摘要与总结共用一套语言**：一行小标签（强调色、字距 0.12em）+ 一段引言，
左侧一道 2px 强调色标线，不画卡片边框。摘要是"这篇文章的一部分"，
画框会把它读成一个嵌进来的外部组件。

**正文外链才加下划线。** 列表里的标题不加——一屏十条，每条挂一条下划线
就变成十条横线，比没有层级更难扫；可点击由整行悬停底色表达。

**纸内留白与纵向节奏（v6.3）**

| 项           | 值                      | 为什么                                                   |
| -            | -                       | ------                                                   |
| 纸内留白     | `32px 40px 96px`        | 28px 时 30px 的标题离纸边只有半行，纸看起来被文字填满    |
| 段距         | `1.25em`（21px）        | 1.8 行高下 1.05em 的段距只比行距多 60%，换行与换段分不清 |
| 标题层级     | h2 21 / h3 18.5 / h4 17 | 原来 h2、h3 都是 18px，比正文只大 1px，层级等于没有      |
| 列表项       | `0.45em`                | 块级元素之间要比行距有更明确的停顿                       |
| 引用 / 图片  | 1.5em / 1.6em           | 同上                                                     |
| 元信息分隔点 | 透明度 .3               | 它只是停顿，不该读出第三个字符                           |

`max-width: calc(100% - 82px)` 的 82 = 左右内边距 80 + 边框 2。
`content-box` 下 `max-width` 约束的是文字宽度、内边距加在外面 ——
改了内边距却不同步这个数，窄视口里纸就会顶出阅读区。

### 5.5 批注与高亮

划词后工具条贴着选区上方浮出：三枚色点 + 一个「批注」。

**批注在工具条内联展开**，不用浏览器原生 `prompt`：

- 原生对话框样式不受控，在白底界面里突然弹出一块系统灰框
- 原生 prompt 的「取消」只返回 null，用户看不到自己写了什么被丢掉

内联输入框配「取消 / 保存」两个按钮，`Esc` 等同取消，`Enter` 等同保存。
取消会**丢弃草稿**并把输入框还原到已保存的值 —— 不这么做的话，
改了一半点取消、再点「加批注」会看到上次的草稿，用户会以为取消没生效。

高亮列表在正文末尾，每条是「色点 + 原文两行 + 批注」；编辑态里同样有
「删除 / 取消 / 保存」三个动作，`Esc` 退出编辑。

### 6.0.1 控件高度阶梯（v6.2）

尺寸不统一是最容易被看见的缺陷，而它从不来自"某个控件写错了"，
而是来自**同一个控件在不同文件里被定义了两次**。所以阶梯只写一处，
其余场景靠容器选择器复用：

| 档位 | 高度    | 令牌                        | 用在哪                                                                                        |
| ---- | ------- | --------------------------- | --------------------------------------------------------------------------------------------- |
| 标准 | 36      | `--btn-h`                   | `.btn`、`.icon-btn`、输入框、下拉、分段控件外框                                               |
| 紧凑 | 28      | `--btn-h-tiny`              | `.btn.tiny`、`.icon-btn.sm`、`.chip`、`.folder-select`、`.bulk-select`、`.feed-ops .icon-btn` |
| 迷你 | 16      | 常量                        | `.icon-btn.tiny` —— 只出现在列表行元信息里，不参与行高                                        |
| 偏高 | 40 / 48 | `--btn-h-lg` / `--btn-h-xl` | 空态与落地页的主行动（`.lg` / `.xl`）                                                         |

**字族可切换（v6.4）。** 三套界面字族 + 三套正文字族，写在 `:root` 的变量上，
由 `<html data-ui-font>` / `<html data-body-font>` 切换（`applyPrefs` 写入）：

| 槽位 | 可选                          | 默认                                  |
| ---- | ----------------------------- | ------------------------------------- |
| 界面 | 思源黑体 / 系统 UI / 微软雅黑 | **思源**（装不到时自动落苹方、雅黑）  |
| 正文 | 宋体 / 黑体 / 楷体            | **宋体**（思源宋体 → 宋体-简 → 宋体） |

每个选项都是**字族栈**而不是单个字体名：装不到的那一档落到下一档，
不会出现"选完变成系统宋体"。不打包字体文件（§4.1）。
字体挂在 `<html>` 而不是 `.reader` —— 只挂阅读区会让弹窗与侧栏保持旧字体，
看起来像两套主题拼在一起。

图标按钮同一套三档：`.icon-btn` 36（工具栏）/ `.icon-btn.sm` 28（弹窗标题行、订阅行内）/
`.icon-btn.tiny` 16（列表行元信息，不参与行高）。**档位写在 class 上，不按容器自动收** ——
按容器收（如 `.feed-ops .icon-btn`）会让同一个 class 出现两个高度，度量脚本与肉眼都会判它"不统一"。

行内按钮的"小"是**场景属性**，不是控件属性 —— 同一个 `.icon-btn` 在工具栏里
是 36，在订阅行里是 28，靠 `.feed-ops .icon-btn` 收，而不是复制一个 class。
手机上由 `@media (max-width: 640px)` 把行内按钮抬回 36/40：触摸目标不跟着桌面一起缩。

### 6.1 按钮的语义

| 变体                | 形态                      | 用在哪                                                 |
| ------------------- | ------------------------- | ------------------------------------------------------ |
| `.btn.primary`      | 实心 `#1e40af` + 白字     | 这个视图**唯一的前进动作**（添加订阅 / 保存）          |
| `.btn`              | 白底 + 1px `#d1d5db` 描边 | 需要被看见的次要动作（重试失效源、空态里的「看全部」） |
| `.btn.ghost`        | 无底无框                  | 集合级低频操作（管理 / 导出 OPML / 导入 OPML）         |
| `.btn.ink`          | 墨底纸字                  | 纸面语境（阅读区正文尾部的「打开原文」），不用主色     |
| `.btn.active`       | 浅蓝底 + 主色字           | 切换类按钮（管理模式）；同时支持 `aria-pressed`        |
| `.btn.danger`       | 淡红底 + 红字             | 行内破坏性动作（取消订阅、删除分组），已有二次确认     |
| `.btn.danger.plain` | 红字、无底无框            | 与主/次按钮同排的破坏性动作（配置台的「删除 Key」）    |
| `.btn.danger.solid` | 实心红                    | **弹窗里确认删除的那一下**，与行内删除重量不同         |

主次靠**底色**分层，不靠「有没有边框」。同一排里最多一个实心、一个描边，第三个危险动作
只留字色 —— 三块底色并排等于三个主按钮。

**禁用态要显式给字色与描边。** 主按钮的字是白的、描边是主色，而禁用只换底色，
不写就会被渲染成"白字压白底的蓝框"。`.btn.primary/.ink/.danger/.danger.solid:disabled`
统一用 `--fg-dim` + `--border`。

质感来自**每一层都只在 1~2px 的量级上做事**：

| 项   | 做法                                                                        | 为什么                                                            |
| -    | ----                                                                        | ------                                                            |
| 阴影 | rest `0 1px 2px rgba(15,23,42,.06)` → hover `0 4px 12px rgba(15,23,42,.08)` | 只有两级。重阴影（shadow-2xl 一类）会让界面发脏                   |
| 上浮 | hover `translateY(-2px)`                                                    | 不超过 2px；再多就开始"轻浮"                                      |
| 按压 | active `scale(.98)` 且取消上浮                                              | 不小于 .98；没有 active 反馈，按钮就是装饰                        |
| 动效 | 150ms `ease-out`                                                            | 上限 200ms                                                        |
| 焦点 | `0 0 0 2px var(--ring-offset), 0 0 0 4px var(--focus-ring)`                 | **必须带 2px offset**，否则环贴在描边上等于没有。这是无障碍底线   |
| 禁用 | opacity .5 + 灰底 + 去掉阴影                                                | 它不再可点，就不该继续"浮"着                                      |
| 加载 | `aria-busy`，文字转透明但**仍占位**，`::before` 转 spinner                  | 宽度零跳变；`transition-property: none` 避免文字与 spinner 叠一瞬 |

**全部由 CSS 变量驱动**：`--btn-bg` / `--btn-bg-hover` / `--btn-fg` / `--btn-bd` / `--btn-shadow` / `--btn-lift`，
变体只覆盖变量、复用同一个 `.btn` 基类；暗色只覆盖变量，不重写结构。
图标按钮视觉 36（行内 18），命中区一律用 `::after` 撑到 44×44，且必须有 `aria-label`。

**不用渐变按钮**：主色实心即可，渐变会让"企业感"变成"营销落地页"。

### 6.2 卡片

白底 + 1px `#e5e7eb` + 12px 圆角 + 24px 内边距 + `0 1px 2px` 阴影。
hover 时阴影升到 `0 4px 12px`；**只有本身可点击的卡片才额外上浮 2px**（`.is-clickable`）。
功能卡的图标容器 40×40、12px 圆角、浅蓝底，hover 时填充主色、图标转白、放大 1.1。

容器上浮是在暗示"这里可以点"。配置台一整页都是不可点容器，鼠标横穿时六张卡依次抬起，
读起来是界面在抖，而不是界面在回应 —— 上浮留给真的能点的那几张。

### 6.3 输入框

白底 + 1px `#d1d5db` + 8px 圆角 + 高 36（`--btn-h`）+ `padding: 0 12px`。
标签 14px / 500，帮助文字 12px Slate。聚焦时描边转主色并加 2px offset 的焦点环，
**不改变盒子尺寸**（用 box-shadow 而不是 border 加粗）。

输入框与同一排的按钮同高（36）。两者不同源时差 2px，一排里会显出一个"不一样的"，
那正是订阅页反复返工的地方。

#### 搜索框

搜索框不是"一个带放大镜的 input"，它是**一个字段**：左侧图标、中央输入区、
右侧动作区（快捷键键帽或清除键）三件套，共用 `.search-box` 容器。

| 部位       | 规格                                                        | 说明                                           |
| ---------- | ----------------------------------------------------------- | ---------------------------------------------- |
| 容器       | `position: relative` + flex 居中                            | 图标与右侧动作都绝对定位，不参与输入区宽度     |
| 输入框     | 高 38、8px 圆角、1px `#d1d5db`、`padding: 0 40px 0 34px`    | 左右留白给图标与键帽，文字不会压到它们         |
| 放大镜     | 左 12px、15px、`--fg-faint`；**聚焦时转主色**               | 一个字段只有一套高亮语言：描边、环、图标同时变 |
| 快捷键键帽 | 右侧、20×20、mono 12、`--bg-elev2` 底 + 1px 描边 + 4px 圆角 | **真实元素**，不是 placeholder 里的字符        |
| 清除键     | 右侧、26×26、圆形、hover 给 `--bg-active`                   | 与键帽互斥占同一位置                           |
| 聚焦       | `border-color: var(--accent)` + 2px offset 环               | 与按钮同一套                                   |
| 悬停       | `border-color: #9ca3af`                                     | 比静止深一档，暗示可输入                       |

三条「不要」，都是这一版改掉的复古写法：

1. **不要把快捷键写进 placeholder**（如 `搜索标题、摘要…  /`）。
   placeholder 一输入就消失，用户永远学不会那个快捷键；而且 `…` + `/` 的尾巴
   是命令行时代的排版习惯。
2. **不要只有一个方框 + 放大镜**。图标在框外、边框与按钮不同源，看起来像
   2008 年的站点搜索条。
3. **不要只靠退格清除**。有内容时必须给 × ；没有内容时那个位置放键帽，
   两者不会同时出现，也不会让右侧空出一块。

### 6.4 状态徽标

全圆角、12px / 500、`padding: 4px 10px`。默认浅蓝底配主色字；
成功用浅绿底配 Confirm Green；提示用 1px 描边而不用填充。
**永远带一行小圆点或图标**，不只靠颜色传达状态。

规则是**同类控件同圆角、圆角随尺寸单调**，而不是"统一成一个数"。

## 七、动效

| 场景         | 时长  | 曲线                    |
| ------------ | ----- | ----------------------- |
| 悬停 / 激活  | 150ms | **ease-out**            |
| 卡片悬停     | 150ms | ease-out（位移 + 阴影） |
| 列表进入     | 120ms | ease-out，opacity 0→1   |
| 折叠展开     | 150ms | ease-out                |
| 刷新图标旋转 | 700ms | linear，循环            |

**全部动效上限 200ms**：超过它，界面就从"利落"变成"轻浮"。
曲线统一用 `ease-out` —— 进场快、收尾缓，是"东西落到位置上"的物理直觉。

不做入场编排、不做视差、不做滚动触发动画。
`prefers-reduced-motion: reduce` 下全部降到 1ms 并去掉位移，只保留颜色变化：
动效敏感用户不该失去状态反馈，只是不再有位移。

## 八、响应式

### 8.1 三档断点

| 宽度       | 布局                                     |
| ---------- | ---------------------------------------- |
| > 1280px   | 三栏 + 侧边目录                          |
| 900–1280px | 三栏，隐藏侧边目录，纸面自适应           |
| < 900px    | 侧栏 + 列表，阅读区为全屏浮层            |
| < 640px    | 单列列表 + 底部 tab 条，阅读区为全屏浮层 |

响应式规则集中在 `mobile.css`，桌面规则集中在 `styles.css`。两处各写一套断点会互相覆盖出难以复现的中间态。

### 8.2 移动端不是桌面缩小版

| 桌面         | 手机                | 原因                          |
| ------------ | ------------------- | ----------------------------- |
| 左侧栏       | 底部 tab 条（5 项） | 390px 下侧栏吃掉一半宽度      |
| 三栏并排     | 列表 / 阅读互斥     | 三栏在 390px 下每栏不到 130px |
| hover 出操作 | 操作常驻            | 触摸没有 hover                |
| 日期栏 52px  | 收窄到 44px         | 把宽度还给标题                |

硬约束：触摸目标 ≥ 44px、输入框字号 ≥ 16px、底部留白 ≥ 56px + 安全区、横向溢出为 0、横屏（`max-height: 480px` 且 `max-width: 900px`）隐藏侧栏与 tab 条。

### v5.0 —— 改为 Apple 设计语言

v4.0 的按钮虽然补齐了状态，但观感仍是"扁平 + 描边"：白底块、1px 硬边、线性位移。

### v6.4 —— 字族开放给用户选

需求方原话：「这个字体更换一下，或者将各部分字体开放让我自己选择」。

原来的 `--font-sans` 是写死的一条栈（Inter + 系统 UI），用户无法改。
现在拆成**两个槽位 × 三档**，都能在阅读偏好面板里切：

| 槽位                              | 可选                          | 默认         |
| --------------------------------- | ----------------------------- | ------------ |
| 界面（侧栏 / 列表 / 设置 / 按钮） | 思源黑体 / 系统 UI / 微软雅黑 | **思源黑体** |
| 正文（阅读区）                    | 宋体 / 黑体 / 楷体            | **宋体**     |

为什么默认界面从「系统」改成「思源」：Windows 上「系统」会落到微软雅黑，
小字号下字面偏窄、笔画粘连，是"看起来旧"的主要来源之一。
思源那一档装不到时自动落到苹方 / 雅黑 —— 不会变丑，只是回到系统默认。

实现要点：

- 每个选项是**字族栈**不是单个字体名（不打包字体文件，§4.1）。
- 变量挂在 `<html>` 上而不是 `.reader`：只挂阅读区会让弹窗与侧栏保持旧字体。
- `--font-sans` 的 `:root` 初值就是思源那一档，与 `DEFAULT_PREFS.uiFont = 'noto'` 对齐 ——
  否则首帧会先渲染系统字体再闪成思源。
- 老 localStorage 数据里没有这两个字段：`loadPrefs` 逐项回退到默认值，不重置其它项。

### v6.6 —— 列表密度与栏宽都开放配置

需求方原话：「或者还有一种办法，将列表中不同问题区分明显，放大列表宽度，
各部分添加部分间隔，可以显示更多摘要。这种也放开配置」。

这与 v6.5 的「只显示标题」**不是替代关系，是一件事的两端**：
信息量越少扫得越快，信息量越多越不用点开。两者都对，取决于此刻是在浏览
还是在挑选。所以两条都留，做成偏好。

**列表密度三档**

| 档                    | 内容                            | 行高              | 一屏      |
| --                    | ----                            | ----              | ----      |
| 紧凑 compact          | 只有标题                        | 43 / 62 / 64px    | **13 条** |
| 标准 standard（默认） | 标题 + 一行摘要 + 元信息        | 78 / 98px         | **8 条**  |
| 舒展 rich             | 标题（3 行）+ 两行摘要 + 元信息 | 115 / 136 / 157px | **5 条**  |

**列表栏宽三档**：368 / 460 / 560px。

实现上三个决定：

1. **组件始终渲染三部分**，显示多少只由 `<html data-list-style>` 决定。
   按偏好条件渲染会让"切一下密度"变成整列表重渲染（30 条会闪一下），
   而且 `.entry-site` / `.entry-time` 时有时无，验收脚本与读屏都得跟着改。
2. **栏宽写成变量再由 `min()` 夹住**：
   `--list-w: min(var(--list-w-user), calc(100vw - var(--sidebar-w) - 594px))`。
   不内联改 `.app` 的 `grid-template-columns` —— 那个模板在 mobile.css 的
   三个断点里各有一份（184/344、320、0/100%），内联覆盖会把移动端规则一起压死。
3. **三档而不是滑块**：密度是排版组合（行内边距 / 标题行数 / 摘要行数 /
   分隔线深浅要一起变），连续可调只会得到大量"哪里都不太对"的中间态。

**顺带修掉两个真 bug**

| 症状                       | 根因                                                                  | 修法                                                                       |
| -------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 当天首行比别的行高 15~46px | `.day-mark` 在网格里占一格（还跨三行），它 33px 高、元信息行只有 16px | 改成绝对定位，与文字共用 `--entry-pad-y`                                   |
| 元信息行被拉到 33px        | 网格项默认 `stretch`，第一列有日号时整行被拉伸                        | `.entry-meta` / `.entry-title` / `.entry-summary` 全部 `align-self: start` |

**验收**：新增 `m1-26-list-density`（13 条断言）。判据不是"看起来对"，而是：

- 三档**信息量单调递增**（量可见文字块的高度之和，不数元素个数 ——
  元素一直都在 DOM 里，数个数永远相等）
- 摘要**实际行数** = 元素高度 ÷ 行高（声明里的 `line-clamp` 不算数）
- 三档行高区间**互不重叠**（重叠就意味着切了跟没切一样）
- 日号不参与行高 —— 做**同一行的 A/B**（摘掉 `.day-mark` 前后高度差必须为 0）。
  第一版拿"首行 vs 次行"量，三档全红：两行标题长度本来就不同，
  量出来的是内容差，不是日号造成的高度差。

`m0-09` 的行高区间跟着默认档改（70~120），`m1-19` 的首屏条数 9 → 7。

  每个月 4 个不同日子；数据只覆盖一天的话这条断言会变成空转）
- ⑥ 宽度的取值改到 456，因为 1440 下 456 才不会被 clamp 掉

### v6.8 —— 列表滚动到底自动加载

需求方原话：「列表下拉栏应该自动加载，而不是点击加载」。

改前底部是两个 `.btn`：主列表一个「加载更多」、尾段一个「继续加载更早的 N 条」。
现在换成 **1px 哨兵 + 一行状态提示**，两处翻页都由 `IntersectionObserver` 触发。

| 状态   | 显示                | 可点   |
| ------ | ------------------- | ------ |
| 加载中 | `⟳ 正在加载…`       | 否     |
| 已到底 | `没有更多了`        | 否     |
| 失败   | `加载失败` + `重试` | **是** |

**为什么用 observer 而不是 scroll 事件** —— 三条，第 2 条是决定性的：

1. `scroll` 每条事件都要量 `scrollTop + clientHeight + scrollHeight`，那是每帧
   一次强制同步布局（layout thrashing），长列表能摸出来；observer 由合成线程算。
2. **内容不够高时根本不产生 scroll 事件** —— 搜索结果只有 3 条、一屏装得下，
   `scroll` 方案下那一页永远取不到。observer 下哨兵一开始就在可见区内，立刻触发。
3. `rootMargin: 0px 0px 320px 0px` 是提前量：等哨兵真进可见区才请求，用户会
   先看到一帧空白。320px ≈ 三四行，请求在路上时正好读完当前这几行。

**失败态为什么必须有按钮**：自动加载失败时不给人重试入口，等于把列表卡死在原地。
这是"自动"最容易出的事故，所以三档状态里只有这一档是可点的。
失败时**不写 `setErr`** —— 那会在列表顶部弹一条红条，而用户已经在底部了看不到，
而且他并没有主动做任何操作，弹错误像是对着用户喊。

**两个容易漏的守卫**：

| 守卫                             | 漏了会怎样                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `if (view === 'history') return` | 历史走 `listHistory`，`load()` 走 `listEntries`，服务端把未知 view 当 inbox —— 滚到底会往历史列表里插一批未读 |
| 主列表还有游标时不触发尾段       | 两段内容交错插入，列表顺序全乱                                                                                |

**验收**：新增 `m1-27-auto-load`（9 条）。第 ④ 条是关键 ——
把视口抬到 **3600px** 让一页 30 条整个装进一屏，此时用户**一次都不用滚**：
`scroll` 方案下永远是 30 条，observer 方案会自己追加到 60 条。
这是两种实现唯一能互相区分开的场景（第一版我写的是"搜一个词看条数"，
结果两种实现都能过，等于没测）。

**顺带**：CSS gzip 实测 15.5 KB，`m0-10-resources` 的预算从 15 提到 **17 KB**。
新增了三档密度、六套字族栈、自动加载三态，不是"放宽标准"，是把预算调到与
功能规模一致 —— 预算的意义是拦"意外膨胀"，不是拦"有意增加的功能"。

### v6.9 —— 配置台的尺度收口

需求方原话：「这两页看着丑、不统一」。量化之后不是审美分歧，是八处可测的缺陷，
按影响排序前三条都在配置台：

| 缺陷                                             | 根因                                                       |
| ------------------------------------------------ | ---------------------------------------------------------- |
| 「管理 / 导出 / 导入」三颗描边按钮并排成"四块砖" | §6.1 早写明这三个用 `.btn.ghost`，代码用的 `.btn`          |
| 卡片里的字段只有 32px 高、标签 12px              | `padding: 7px 10px` + 13px 字，与 §6.3 的 36 / 14·500 无关 |
| 一排五个 28px 图标的命中区互相压盖 14px          | `.icon-btn::after` 撑到 44×44 是为**孤立**按钮设计的       |

**命中区那条是唯一的操作错误**：中心距 30、命中区 44，相邻两个矩形重叠 14px，
DOM 靠后的那个赢 —— 点左边图标的右沿，事件落在右边的邻居上。修法是两件事一起做：
间距 2 → 6（中心距 34），行内按钮的 `::after` 不再外扩（行本身有 68px 高，不缺命中区）。

**三处判定，写下来免得下次再争**：

1. **不引组件库。** 只用到 8 类控件，为此带 40+ 组件文件与一条 CSS 构建链路；
   `.btn` 的六种变体已由 `--btn-*` 变量驱动。缺的是尺子，不是组件 —— 组件库不替
   这件事做决定，只会再给一份第二真相。
2. **不用渐变。** 进度条从 3px 提到 6px，填充色改按档位（正常主色 / 降级警告黄 /
   暂停危险红）。渐变会把状态编码变成装饰，而这个条存在的理由是回答"为什么没分析"。
3. **不把行内操作藏到 hover。** 键盘用户会失去可见性；减噪靠"静止 55% 不透明度 +
   加间距"，`hover` 与 `:focus-within` 一起拉满。

**顺带补掉的四个真缺陷**（都是渲染出来才看见的）：

- 禁用态的主按钮是**白字压白底** + 一个蓝框：「保存 Key」在没输入 key 时就是禁用态，
  也就是它最常被看到的样子是一个空框。
- 订阅行高度 67/68 交替：只有"非首行"画分隔线，首行矮 1px。改成每行都画上边，
  组头不再自带下边线（否则 2px 双线）。
- `.settings-card` 与 `.settings-modal` 同为纯白，边界只能由 1px 描边承担 → 四张卡
  叠起来像一张表。内容区改 `--bg-sunken`，卡片留白。
- `.settings-modal` 是两套遮罩（`rgba(4,6,10,.62)` 无虚化）与 16px 圆角里的那一个，
  与 `.modal` 的 12 + 虚化 2px 不同源。统一到 `--scrim` / `--scrim-blur`。

**验收**：`typecheck:all` + 90 个单测 + `build:client`；UI 脚本 `m0-09` / `m1-05` / `m1-06` /
`m1-08` / `m1-10` / `m2-08` 全绿，新增 `m1-28-settings-scale`（11 条，守命中区不压盖、
行内操作不完全透明、内容区底色 ≠ 卡片底色、禁用态主按钮对比度 ≥ 2.5:1）。

`m1-13-settings` 有 5 条红，**与本轮无关**：那 5 条靠 `window.confirm` 的桩验证"删组有确认框"，
而删除早已改成 Promise 化的 `useConfirm`（应用内弹窗），桩不会触发 —— 弹窗一直挂着，
组自然没删掉。修法是照 `ConfirmDialog` 的 DOM 点确认按钮，而不是继续 stub `window.confirm`。
