# 澄 · 分组与源排序方案

## 一、要解决的问题

`folders.sort` 一直存在：建分组时写 `MAX(sort)+1`，读取时 `ORDER BY f.sort, f.name`。
但**没有任何能改它的入口** —— `PATCH /folders/:id` 只接受 `name`，前端也没有排序相关
代码。用户看到的分组顺序，实际就是"当初建它们的顺序"，建歪了只能改数据库。

源更彻底：`feeds` 表**没有** `sort` 列，顺序由 `ORDER BY status='broken', title` 决定，
是"如果没坏就按标题"。所以源既不能排，也不能摆。

需求方原话：「我希望可以在分组栏长按，去调整分组顺序等」。

## 二、目标

1. 长按分组行或源行 → 进入排列模式；拖动或点 ↑↓ 调序。
2. 源可以跨组移动：拖到某个分组行上 = 放进该组；拖到未分组区 = 移出组。
3. 顺序落到数据库（`folders.sort`、新增 `feeds.sort`），刷新、换设备、备份恢复后仍在。
4. 进入/移出分组时给可见提示，可撤销。
5. 配置 › 分组 里有一套**始终可用**的手动箭头，不用长按、不需要先进入任何模式。
6. 全键盘可用：↑↓ 是真实按钮，可 Tab 到达。

## 三、非目标

- **不做分组嵌套**。仍是一层扁平结构，理由见 `src/server/feeds/folders.ts` 头注释。
- **不做拖到边缘自动滚动**。分组与源通常一屏放得下，超过一屏时拖到边缘不会滚，
  这是已知限制，不是遗漏。
- **不做"按名称排序"一键按钮**。排序的对象是人脑里的重要性，不是字符串。

## 四、侧栏结构（本次调整）

未分组源**移到最前面**，排在所有分组行之前；分组行按 `folders.sort` 排在后面。

```
  分组                      ← 区块标题
  · 散源甲            12    ← 未分组源（在最前）
  · 散源乙             3
  ⌄ 科技 IT            59    ← 分组行
    源 A               21    ← 组内源（展开时）
    源 B               38
  ⌄ 长知识              9
  ⌄ 编程              301
```

这个位置是需求方本轮明确要求的（原先在最后）。**它推翻了 `PLAN.md` §15.26
里「固定排在所有分组之后」那一行**，文档要跟着改。`m1-26` ① 只断言未分组行之间
的拼音序、不断言它们在分组之后，所以既有断言不会红。

未分组行仍然**不造伪分组**（§15.26 的结论不变）：它是个不可展开的行，
只是顺序位置变了。

## 五、交互

### 5.1 两个入口

| 入口 | 动作 | 适用 |
|---|---|---|
| 侧栏的任意分组行 / 源行 | 按住 500ms | 桌面鼠标 / 触屏 |
| 配置 › 分组 | ↑↓ 按钮，常显 | 手机 / 键盘 / 找不到长按的人 |

两条路改的是同一份数据，但**不动同一套界面状态**：侧栏是拖拽模式，
配置页是常驻箭头。

### 5.2 长按判定

`pointerdown` 起 500ms 定时器，下列任一情况取消：

- `pointermove` 累计 > 8px（那是拖拽或滑动，不是按住）
- `pointerup` / `pointercancel`
- `contextmenu`

取消后若是 `pointerup` 且未超位移阈值，**照常当点击**（选中分组/源）。

500ms 的来历：低于 400ms 会和"点一下选中"抢手势，点得稍慢就误进模式；
高于 600ms 又显得没反应。8px 是触摸抖动容差。触发时 `navigator.vibrate(10)`。

### 5.3 长按后的视觉（常规做法）

长按生效的瞬间到松手落位，全程要有"这个东西现在归我手管"的信号：

| 阶段 | 表现 |
|---|---|
| 长按触发 | 行轻微放大到 1.02、底色变 `--bg-elev`、加 `--shadow` 浮起，其余行降为 0.72 不透明度 |
| 拖动中 | 浮起的那行跟着指针走（`position: fixed` + `transform`），原位置留一条 2px 高的淡色占位，不是完整空行 |
| 悬停在行间 | 目标行上/下边缘出现 2px `--accent` 落点线；同一时刻只有一条 |
| 悬停在分组行上 | 整个分组行底色染成 `--accent-soft` + 1px `--accent` 描边，表示"放进去"，此时不画落点线 |
| 悬停在自己原来的位置 | 落点线不出现，不产生"可以放这里"的错觉 |
| 拖到窗口外 / `Esc` | 浮起行退回原位，顺序不变 |

浮起时用 `pointer-events: none` 关掉浮起行自身的命中，否则它永远在指针正下方，
落点判定会一直命中它自己。

### 5.4 进入 / 移出分组的提示

按下落位后，窗口底部中间出现一条 toast（手机上抬到 tab bar 之上），2.6 秒自动消失：

```
  ✓  「阮一峰的网络日志」已移入「科技 IT」   撤销
  ✓  「阮一峰的网络日志」已移到未分组         撤销
```

- 「撤销」把这一步完整回滚（`folderId` 与原 `sort` 一起），再弹一条"已撤销"。
- 撤销只在最后一次操作后 2.6 秒内有效；超时后按钮消失，toast 自行淡出。
- **同组内纯调序不弹 toast** —— 那是原地微调，弹窗反而吵。只有跨组才提示。
- 失败时同一位置换成红色 toast，文案带原因，**不自动消失**，要人点掉。

### 5.5 提交时机

**每次落位/点一次箭头就提交一次**，不攒到「完成」。攒着的话排到一半刷新、
切标签、来电话，攒着的调整全部丢失，而且丢得无声。「完成」只负责退出模式。

### 5.6 退出排列模式

「完成」按钮、`Esc`。点侧栏其他地方**不**退出 —— 误触一下就把现场清掉更难受。

## 六、配置 › 分组 的手动方式

不依赖长按，也不要任何"进入模式"：

- 每个分组行右侧常显 **↑ ↓**，点一次走一格；首行 ↑ 与末行 ↓ 置灰禁用。
- 每个分组左侧一个展开箭头，展开后列出组内源，同样每个源带 **↑ ↓**。
- 每个源行尾部一个「移到…」下拉（`<select>`），把源在组之间搬。不用拖。
- 所有改动提交与侧栏同一套接口，成功后 `reload()`，侧栏跟着变。

为什么用常显箭头而不是复用侧栏的拖拽：配置页是**批量整理**的场合，一次要动十几项，
箭头每点一次都是明确的"上移一格"，不会出现拖偏了却看不出来的情况；
而且它天然可键盘操作、可被断言精确验证。

## 七、数据与接口

### 7.1 新增 `feeds.sort`

```
0007_feed_sort.sql
ALTER TABLE feeds ADD COLUMN sort INTEGER NOT NULL DEFAULT 0;
```

老数据全是 `0`，并列时退回按标题比 —— 现有顺序不变，界面上看不出这次迁移。

`listFeeds` 的排序改为：

```sql
ORDER BY f.status = 'broken', f.sort, f.title
```

失效源仍排最后（§15.23），之后才看 `sort`。前端对未分组源仍用
`sort` 优先、`zh-CN` 拼音兜底的比较器 —— **不能**让 SQLite 的 BINARY
排序接手并列项，那会给出"七 < 三 < 零"（`m1-26` ① 抓的就是这个）。

### 7.2 分组排序

```
PATCH /api/v1/folders/reorder
  body  { ids: string[] }
  → 200 { items: FolderWithCount[] }
```

- `ids` 里每个 id 必须属于当前用户，否则 400，且顺序**不变**。
- 只给一部分 id 合法：列出的按 `ids` 顺序拿 `sort = 0..n-1`，未列出的
  保持原相对次序排在后面（另一个标签页刚建的分组不会因此错乱）。
- 空数组 / 非数组 → 400。事务内 UPDATE，一次 COMMIT。

### 7.3 源的排序与跨组

```
POST /api/v1/feeds/arrange
  body  { folderId: string | null, ids: string[] }
  → 200 { ok: true, moved: number }
```

语义是「这批源现在归 `folderId`，顺序就是 `ids`」：先校验 `folderId`
与全部 id 归属，再在一个事务里写 `folder_id` 与 `sort = 0..n-1`。
组内调序、移入某组、移出到未分组，都是同一句话的不同参数，不需要三个接口。

未列出的同组源保持相对次序、排在后面 —— 与 7.2 同一条规则。

### 7.4 路由顺序

⚠️ `PATCH /folders/reorder` 必须注册在 `PATCH /folders/:id` **之前**。
Hono 按注册顺序匹配，反了的话 `"reorder"` 被当成分组 id，接口永远 404
「分组不存在」。`/folders/unfile/feeds` 与 `/feeds/bulk/refresh` 都踩过同一个坑，
源码里都有注释。`POST /feeds/arrange` 同样要排在 `/feeds/:id/*` 之前。

## 九、我做的三个决定（可以否决）

1. **未分组块最前，但不加「未分组」标签行**。加一行标签要吃 20px，而区块标题
   已经在上面；辨识靠未分组行没有展开箭头、不能展开。若实测看起来像分组，
   再加标签。
2. **进入排列模式时收起全部手风琴**。展开的组行高几十像素，落点计算会漂；
   拖动时子行跟着父行走还会让整块跳。
3. **拖柄放箭头位，不让箭头兼作拖柄**。排列模式下箭头点了没意义，
   复用要人试一次才明白。

## 十、验收

新增 `m1-27-arrange.mjs`，与既有脚本一起跑。至少覆盖：

- `PATCH /folders/reorder [C,A,B]` 后 `GET /folders` 就是 C,A,B
- 提交未知 id → 400 且顺序不变；只提交一个 id → 它第一、其余相对次序不变
- `ids` 非数组 / 空数组 → 400
- `POST /feeds/arrange` 把源移进另一组：`folderId` 与 `sort` 都变，移出同理
- 长按满 500ms 进入排列模式；按不满松手 → **不进入**且照常选中
- 位移 > 8px 再松手 → 不算长按，也不当点击
- 排列模式下点 ↓ → 顺序变化且 `GET` 跟着变（不是只有 DOM 动了）
- 浮起态存在：长按后原行 `transform` 非 none 且有阴影；松手后回到 none
- 跨组落位弹出 toast，文案含源名与目标组名；2.6s 后消失
- 点「撤销」→ 源回到原组原位置
- 配置 › 分组：↑ 在第一行禁用、↓ 在最后一行禁用；点 ↓ 后顺序变化
- 配置里组内源的 ↑↓ 与「移到…」生效
- 375px 下配置页箭头与 toast 不横向溢出
- 未分组块在分组行**之前**（`getBoundingClientRect().top` 比较）

**既有约束不能破**：`m1-18`（点分组行 = 选中并展开）、`m1-26`（未分组行同级、
拼音序、不重复渲染）、`m0-09`（行高）、`m1-10`（圆角四档）、
`m1-05`（手机触摸目标 ≥44px）都要继续绿。
